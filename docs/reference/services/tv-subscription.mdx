# TV subscription
Use the TV subscription API to pay for DStv, GOtv, StarTimes, and Showmax subscriptions.
Every provider uses the same endpoints. What changes is whether you verify first and which extra fields you send.

## Providers

The following table lists the providers and how they differ:

| Provider | `serviceID` | `billersCode` | Verify first | Renew current bouquet | Returns |
| :--- | :--- | :--- | :--- | :--- | :--- |
| DStv | `dstv` | Smartcard number | Yes | Yes | None |
| GOtv | `gotv` | Smartcard number | Yes | Yes | None |
| StarTimes | `startimes` | Smartcard or eWallet number | Yes | No | None |
| Showmax | `showmax` | Phone number | No | No | A voucher code |

:::info

Make sure you have done the following: [integrate with VTpass API](/docs/tutorials/getting-started/integrate-with-vtpass-api), [API key authentication](/docs/tutorials/getting-started/create-api-key), and [Whitelist products](/docs/tutorials/getting-started/whitelist-products)

:::

## Endpoints

The following table lists the TV subscription endpoints:

| Action | Method | Sandbox URL | Live URL |
| :--- | :--- | :--- | :--- |
| Get bouquets | `GET` | `https://sandbox.vtpass.com/api/service-variations?serviceID={serviceID}` | `https://vtpass.com/api/service-variations?serviceID={serviceID}` |
| Verify smartcard number | `POST` | `https://sandbox.vtpass.com/api/merchant-verify` | `https://vtpass.com/api/merchant-verify` |
| Pay | `POST` | `https://sandbox.vtpass.com/api/pay` | `https://vtpass.com/api/pay` |
| Check transaction status | `POST` | `https://sandbox.vtpass.com/api/requery` | `https://vtpass.com/api/requery` |

Send the `api-key` and `public-key` headers with `GET` requests, and the `api-key` and `secret-key` headers with `POST` requests.

## 1. Get bouquets
Get the provider's bouquets (subscription plans) with the [Variation codes API](/docs/tutorials/services/variation-codes). Use the `serviceID` from the [provider table](#providers).

```js
curl --request GET \
  --url "https://sandbox.vtpass.com/api/service-variations?serviceID=dstv" \
  --header "api-key: YOUR_API_KEY" \
  --header "public-key: YOUR_PUBLIC_KEY"
```

```json
{
   "response_description":"000",
   "content": {
      "ServiceName":"DSTV Subscription",
      "serviceID":"dstv",
      "convinience_fee":"N0",
      "variations": [
         {
            "variation_code":"dstv-padi",
            "name":"DStv Padi N1,850",
            "variation_amount":"1850.00",
            "fixedPrice":"Yes"
         },
         {
            "variation_code":"dstv79",
            "name":"DStv Compact N7900",
            "variation_amount":"7900.00",
            "fixedPrice":"Yes"
         },
         ...
      ]
   }
}
```

Show `name` and `variation_amount` to your customer, and keep `variation_code` to send when they pay.

:::tip

Bouquet prices change often. Don't hardcode variation codes: fetch them regularly, or keep them in sync with the [variation codes update webhook](/docs/how-to/webhooks/variation-codes-update-webhook).

:::

## 2. Verify the smartcard number
DStv, GOtv, and StarTimes only. Skip this step for Showmax.

Always verify the smartcard number before you take payment, so the customer can confirm the name on the decoder.

<Tabs>
  <TabItem value="curl" label="Curl" default>
   ```js
  curl --request POST \
  --url "https://sandbox.vtpass.com/api/merchant-verify" \
  --header "api-key: YOUR_API_KEY" \
  --header "secret-key: YOUR_SECRET_KEY" \
  --header "Content-Type: application/json" \
  --data '{"billersCode": "1212121212", "serviceID": "dstv"}'
   ```
  </TabItem>
  <TabItem value="js" label="Javascript">
    ```js showLineNumbers
    const BASE_URL = "https://sandbox.vtpass.com/api"; // Switch to https://vtpass.com/api for live

async function verifySmartcard({ serviceID, smartcardNumber }) {
  const response = await fetch(`${BASE_URL}/merchant-verify`, {
    method: "POST",
    headers: {
      "api-key": "YOUR_API_KEY",
      "secret-key": "YOUR_SECRET_KEY",
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ billersCode: smartcardNumber, serviceID }),
  });

  const data = await response.json();

  if (data.code !== "000" || data.content?.WrongBillersCode) {
    throw new Error(`Smartcard verification failed: ${JSON.stringify(data)}`);
  }

  return data.content;
}

verifySmartcard({ serviceID: "dstv", smartcardNumber: "1212121212" })
  .then((customer) => console.log(customer.Customer_Name, customer.Status))
  .catch((err) => console.error(err));
    ```
  </TabItem>
</Tabs>

The following table describes the request body fields:

| Field | Required | Type | Description |
| :--- | :--- | :--- | :--- |
| `billersCode` | Yes | `string` | Smartcard number. In sandbox, use `1212121212` |
| `serviceID` | Yes | `string` | `dstv`, `gotv`, or `startimes` |

### Expected response
DStv and GOtv:

```json
{
   "code":"000",
   "content": {
      "Customer_Name":"TEST METER",
      "Status":"ACTIVE",
      "Due_Date":"2025-02-06T00:00:00",
      "Customer_Number":"8061522780",
      "Customer_Type":"DSTV",
      "commission_details": {
         "amount":null,
         "rate":"1.50",
         "rate_type":"percent",
         "computation_type":"default"
      }
   }
}
```

StarTimes:

```json
{
   "code":"000",
   "content": {
      "Customer_Name":"TestMan Decoder",
      "Balance":54.82,
      "Smartcard_Number":"1212121212",
      "WrongBillersCode":false,
      "commission_details": {
         "amount":null,
         "rate":"2.50",
         "rate_type":"percent",
         "computation_type":"default"
      }
   }
}
```

The following table describes the verification fields and which providers return them:

| Field | Provider | Description |
| :--- | :--- | :--- |
| `Customer_Name` | All | Name on the decoder. Show it to the customer to confirm |
| `Status` | DStv, GOtv | Subscription status, for example `ACTIVE` |
| `Due_Date` | DStv, GOtv | Date the current subscription ends. The format differs between DStv and GOtv |
| `Current_Bouquet` | DStv, GOtv | Customer's current bouquet |
| `Renewal_Amount` | DStv, GOtv | Amount to renew the current bouquet. Use it as `amount` when you [renew](#renew-the-current-bouquet-dstv-and-gotv) |
| `Balance` | StarTimes | Balance on the customer's StarTimes account |
| `WrongBillersCode` | StarTimes | `true` if the smartcard number is invalid |

## 3. Pay
How you pay depends on the provider:

- **DStv and GOtv**: show the customer their current bouquet and renewal amount, then ask whether they want to [renew](#renew-the-current-bouquet-dstv-and-gotv) it or [change](#change-bouquet-or-subscribe) to a different one.
- **StarTimes and Showmax**: [subscribe to a bouquet](#change-bouquet-or-subscribe).

### Change bouquet or subscribe
Use this to subscribe a new customer, change a DStv or GOtv customer's bouquet, or pay for StarTimes or Showmax.

<Tabs>
  <TabItem value="curl" label="Curl" default>
   ```js
  curl --request POST \
  --url "https://sandbox.vtpass.com/api/pay" \
  --header "api-key: YOUR_API_KEY" \
  --header "secret-key: YOUR_SECRET_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "request_id": "2025031011029125930",
    "serviceID": "dstv",
    "billersCode": "1212121212",
    "variation_code": "dstv-padi",
    "phone": "08011111111",
    "subscription_type": "change",
    "quantity": 1
  }'
   ```
  </TabItem>
  <TabItem value="js" label="Javascript">
    ```js showLineNumbers
    const BASE_URL = "https://sandbox.vtpass.com/api"; // Switch to https://vtpass.com/api for live

async function subscribe({ requestId, serviceID, billersCode, variationCode, phone, months = 1 }) {
  const body = {
    request_id: requestId,
    serviceID,
    billersCode,
    variation_code: variationCode,
    phone,
  };

  // DStv and GOtv need a subscription type, and accept a number of months
  if (serviceID === "dstv" || serviceID === "gotv") {
    body.subscription_type = "change";
    body.quantity = months;
  }

  const response = await fetch(`${BASE_URL}/pay`, {
    method: "POST",
    headers: {
      "api-key": "YOUR_API_KEY",
      "secret-key": "YOUR_SECRET_KEY",
      "Content-Type": "application/json",
    },
    body: JSON.stringify(body),
  });

  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status} ${response.statusText}`);
  }

  return response.json();
}

subscribe({
  requestId: generateRequestId(), // See the Request ID page
  serviceID: "dstv",
  billersCode: "1212121212",
  variationCode: "dstv-padi",
  phone: "08011111111",
})
  .then((data) => console.log(data.code, data.content?.transactions?.status))
  .catch((err) => console.error(err));
    ```
  </TabItem>
</Tabs>

The following table describes the request body fields:

| Field | Required | Type | Description |
| :--- | :--- | :--- | :--- |
| `request_id` | Yes | `string` | Unique reference for the transaction. Use it to requery the transaction later. See [Request ID](/docs/explanation/request-id-format-and-lagos-time) |
| `serviceID` | Yes | `string` | Provider's service ID. See the [provider table](#providers) |
| `billersCode` | Yes | `string` | Smartcard number, StarTimes eWallet number, or (for Showmax) phone number |
| `variation_code` | Yes | `string` | `variation_code` of the bouquet from [Get bouquets](#1-get-bouquets) |
| `phone` | Yes | `string` | Customer's phone number |
| `subscription_type` | DStv and GOtv only | `string` | Always `change` |
| `quantity` | No | `number` | DStv and GOtv only. Number of months to pay for, for example `1` |
| `amount` | No | `number` | Amount to pay. If you leave it out, VTpass uses the bouquet price. If you send it, VTpass tops up the decoder with that amount |

### Renew the current bouquet (DStv and GOtv)
Use this when a returning DStv or GOtv customer wants to keep their current bouquet.
Send `subscription_type: "renew"` and set `amount` to the `Renewal_Amount` from [verification](#2-verify-the-smartcard-number). You don't need a `variation_code`.

```js
curl --request POST \
  --url "https://sandbox.vtpass.com/api/pay" \
  --header "api-key: YOUR_API_KEY" \
  --header "secret-key: YOUR_SECRET_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "request_id": "2025031011029125930",
    "serviceID": "dstv",
    "billersCode": "1212121212",
    "amount": 1850,
    "phone": "08011111111",
    "subscription_type": "renew"
  }'
```

The following table describes the request body fields:

| Field | Required | Type | Description |
| :--- | :--- | :--- | :--- |
| `request_id` | Yes | `string` | Unique reference for the transaction |
| `serviceID` | Yes | `string` | `dstv` or `gotv` |
| `billersCode` | Yes | `string` | Smartcard number |
| `amount` | Yes | `number` | `Renewal_Amount` from verification |
| `phone` | Yes | `string` | Customer's phone number |
| `subscription_type` | Yes | `string` | Always `renew` |

:::note

The renewal amount can be lower than the bouquet's listed price because of promotions from DStv or GOtv. Always use `Renewal_Amount` from verification, not `variation_amount`.

:::

         "phone":"123450987623",
         "name":null,
         "convinience_fee":0,
         "amount":"1850",
         "platform":"api",
         "method":"api",
         "transactionId":"17416009779459629327738818",
         "commission_details": {
            "amount":27.75,

The response has the same fields as the requery response. See [Response fields](/docs/how-to/handle-pending-transactions-and-requery#response-fields).

A `000` code doesn't always mean the subscription was delivered. Check `content.transactions.status`: only `delivered` means success. If the status is `initiated` or `pending`, [requery the transaction](/docs/how-to/handle-pending-transactions-and-requery). See [Response codes](/docs/reference/response-codes) for every code.

:::

## Showmax: give the customer their voucher
A Showmax payment returns a voucher code instead of activating the subscription directly. Give the code to the customer so they can redeem it on their Showmax account.

```json
{
   "code":"000",
   "content": { ... },
   "response_description":"TRANSACTION SUCCESSFUL",
   "requestId":"2025031013486732084",
   "amount":8400,
   "transaction_date":"2025-03-10T12:48:57.000000Z",
   "purchased_code":"SHMVHXQ9L3RXGPU",
   "Voucher": [
      "SHMVHXQ9L3RXGPU"
   ]
}
```

The following table describes the voucher fields:

| Field | Type | Description |
| :--- | :--- | :--- |
| `purchased_code` | `string` | Voucher code |
| `Voucher` | `array` | List of voucher codes bought |

The requery response also returns `purchased_code` and `Voucher`, so you can get the code again if you lose it.

## Check transaction status
Use the request ID to check the status of any TV subscription. See [Handle pending transactions and requery](/docs/how-to/handle-pending-transactions-and-requery).

## Test in sandbox
In sandbox, the `billersCode` you send decides the result.

The following table lists the sandbox test values:

| `billersCode` | Result | Use it to test |
| :--- | :--- | :--- |
| `1212121212` (Showmax: `08011111111`) | Successful | Verification and a successful payment |
| `201000000000` | Pending | How you handle a pending transaction |
| `500000000000` | Unexpected response | How you handle an unexpected response |
| `400000000000` | No response | How you handle no response |
| `300000000000` | Timeout | How you handle a timeout |
| Any other number | Failed | How you handle a failed verification or payment |
